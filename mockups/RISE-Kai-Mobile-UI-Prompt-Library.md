# RISE / Kai — Prompt Library para Mobile App

## 1. Princípio visual do produto

O RISE não deve parecer uma app de produtividade, uma app clínica ou um jogo infantil. Deve sentir-se como um **mundo pessoal vivo que cresce com o jovem**, entre os 13 e os 18 anos.

**Kai** é o companheiro do jovem: presente, inteligente, próximo e desafiante, mas nunca paternalista.  
**RISE** é o sistema cognitivo de desenvolvimento que observa padrões, organiza progresso, sugere missões e transforma evolução pessoal em sinais visuais.

A cidade/mundo representa desenvolvimento real:
- crescimento = novas estruturas, actividade, luz, vida e detalhe;
- consistência = manutenção de energia e actividade;
- pausa = desaceleração sem castigo;
- perda controlada = menos brilho, menos actividade, elementos adormecidos;
- recuperação = retorno rápido de vida após uma pequena acção;
- legado = conquistas permanentes, nunca destruídas.

# 2. MASTER PROMPT — linguagem visual global

Use este bloco no início de todos os prompts seguintes.

```text
Design a premium mobile app interface for teenagers aged 13–18 called RISE.

RISE is a cognitive personal development system. Kai is the young user's AI companion and guide.

The product must feel aspirational, intelligent, emotionally safe, modern and slightly futuristic, but never clinical, corporate, childish or overly game-like.

Core visual idea: the user owns a living personal world that visually reflects real-life growth. Progress in confidence, learning, creativity, health, relationships, projects and self-knowledge changes the world over time.

Visual language:
- sophisticated Gen Z aesthetic
- immersive 3D or high-end 2.5D world building
- soft cinematic lighting
- clean mobile UI layered over the world
- premium typography
- subtle depth, glass surfaces and soft gradients
- strong visual hierarchy
- calm but emotionally engaging
- expressive without visual overload
- no childish cartoon UI
- no casino-style gamification
- no aggressive streaks
- no red punishment states
- no excessive badges, coins or XP
- progress should feel meaningful rather than addictive

Kai should feel like a trusted companion: warm, observant, curious, calm, slightly playful, never robotic, never a therapist, never an authority figure.

Mobile screen, portrait orientation, approximately 9:19.5 aspect ratio, realistic production-ready app UI, polished interaction design, consistent navigation, plausible typography and spacing.
```

# 3. SCREEN 01 — Home / My World

```text
Create the main home screen of RISE.

Show the user's personal world from a beautiful elevated perspective: a small evolving city surrounded by nature. The world should already have distinct areas representing different dimensions of development.

Visible zones:
- Social District: plaza, cafés, gathering spaces
- Learning District: library and academy
- Health District: park and sports area
- Creative District: studios, music and art spaces
- Projects District: innovation buildings and workshops
- Self-Knowledge District: observatory and quiet garden

The city must feel alive but not crowded.

At the top:
“Your World”
small secondary text: “Built by what you do in real life.”

Show one subtle card:
“Today’s next move”
with a small mission suggested by Kai.

Bottom navigation:
World
Kai
Journey
Progress
Me

Create a strong feeling that this is the user's own evolving place, not a generic game map.
```

# 4. SCREEN 02 — Kai Chat

```text
Create the main Kai conversation screen inside RISE.

Kai is the user's personal development companion.

Do not make this look like a generic AI chatbot.

The background should subtly connect to the user's personal world, perhaps with an animated or blurred view of the current district.

Header:
Kai
small live context indicator: “Understands your journey”

Conversation style:
short, natural, low-pressure messages.

Example:
Kai: “You said speaking up in class still feels harder than it should.”
Kai: “Want to try something small today?”

Suggested response chips:
“Give me a challenge”
“Make it easier”
“Not today”
“Talk it through”

Below, a compact “Real-world action” card can emerge naturally from the conversation.

Kai should feel present and personal without taking over the whole interface.
```

Avoid childish cartoon aesthetics, Roblox-like visuals, Fortnite-like UI, fantasy RPG tropes, casino mechanics, excessive neon, cyberpunk overload, generic SaaS dashboards, clinical wellness app visuals, therapy imagery, hospital colours, smiley mascot clichés, giant XP counters, streak flames, leaderboards, coins, loot boxes, red failure states, cracked buildings, destruction, shame language, parental-control aesthetics, corporate HR software, unrealistic unreadable microtext, overcrowded interface.

# 29. Sequência ideal para um primeiro protótipo visual

Para validar o conceito antes de desenhar dezenas de ecrãs, eu criaria primeiro estes 8:

1. **My World — estado normal**
2. **Kai Chat**
3. **Real-world Mission**
4. **Growth Event**
5. **Controlled Decline**
6. **Reawakening**
7. **Permanent Milestone**
8. **Mature World after one year**

Esta sequência permite testar as quatro hipóteses visuais essenciais do produto:

- o jovem quer possuir e explorar o seu mundo;
- Kai parece um companheiro e não apenas um chatbot;
- crescimento pessoal consegue ser transformado em mudança visual desejável;
- regressão controlada cria tensão suficiente sem produzir punição ou perda emocional.

# 30. Regra de coerência para todos os futuros ecrãs

Antes de aprovar qualquer mecânica visual, aplicar este teste:

**A acção que a interface incentiva melhora a vida do jovem fora da app, ou apenas aumenta o tempo dentro da app?**

Se a resposta for a segunda, a mecânica deve ser redesenhada.

A lógica central do sistema deve manter-se:

**Real life action → evidence → reflection → world change → next choice.**

E a lógica de regressão:

**Legacy never disappears. Current energy can change. Restarting is easy.**
